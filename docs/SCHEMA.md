# Data & Interface Design

No database. The contract between CLI, Bob, CI, and dashboard is a set of JSON/YAML/Markdown files with fixed schemas.

## 1. Config: `.gauntlet/config.yaml`

```yaml
baseRef: main               # diff base for --changed
testCommand: "npm test"     # command Stryker uses per mutant
minScore: 80                # default gate threshold
concurrency: 4              # parallel mutant workers
include: ["src/**/*.ts"]    # mutation candidates (intersected with changed files)
exclude: ["**/*.spec.ts", "**/*.test.ts"]
```

## 2. Run artifact: `.gauntlet/runs/<runId>.json`

`runId` = `<unix-ts>-<short-git-sha>`.

```json
{
  "runId": "1758945600-a1b2c3d",
  "createdAt": "2026-09-26T14:00:00Z",
  "baseRef": "main",
  "headSha": "a1b2c3d",
  "trigger": "hook | manual | strengthen | ci",
  "changedFiles": ["src/pricing.ts", "src/cart.ts"],
  "totals": {
    "mutants": 62,
    "killed": 24,
    "survived": 34,
    "timeout": 2,
    "noCoverage": 2,
    "trustScore": 43.3,
    "lineCoverage": 91.0,
    "durationMs": 142000
  },
  "files": [
    {
      "path": "src/pricing.ts",
      "trustScore": 33.3,
      "mutants": [
        {
          "id": "m-017",
          "mutator": "ConditionalExpression",
          "line": 42,
          "status": "survived",
          "original": "if (qty >= bulkThreshold)",
          "mutated": "if (qty > bulkThreshold)"
        }
      ]
    }
  ],
  "comparedTo": "1758941000-e4f5a6b"
}
```

Field rules: `trustScore = killed / (killed + survived) * 100`, one decimal; `timeout` counts as killed for scoring (Stryker convention); `noCoverage` is excluded from the denominator but displayed as its own warning.

### MVP implementation clarifications

- Raw status counts are disjoint: `killed` excludes `timeout`. The effective killed count used in the formula is `killed + timeout`; score is `(killed + timeout) / (killed + timeout + survived) * 100`. The example above is therefore 43.3%.
- A run with zero scored mutants has `trustScore: null`, not 100. The gate fails closed for null scores, no-coverage-only runs, malformed artifacts, and artifacts from a different HEAD.
- `lineCoverage` is a percentage or `null` when a measured coverage report is unavailable. Never estimate it from mutation outcomes.
- Mutant statuses are `killed`, `survived`, `timeout`, `noCoverage`, `ignored`, `compileError`, and `runtimeError`. Unscored statuses are counted separately when present. Runtime errors must not produce a passing gate.
- `schemaVersion: 1` identifies this contract. `threshold` stores the configured minimum score (default 80). `totals` may additionally contain `ignored`, `compileError`, and `runtimeError` counts.
- Per-file `trustScore` follows the same formula. Mutant IDs need only be unique within each file; UI keys use file path plus ID.
- `runId` may include millisecond timestamps to avoid collisions. Artifact writes use a temporary file plus rename. The same contract applies to committed sample artifacts generated by the CLI.
- `strengthen` performs one bounded Bob invocation and one verification run; repeated attempts are explicit user invocations. It checks source changes and test deletions and reports failures; prompt instructions alone do not guarantee unchanged assertions.
- `strengthen --prepare-only` creates the survivor handoff without claiming a Bob execution. The configured Bob command is an explicit opt-in until actual IBM CLI flags are verified.
- Source scope is the union of the base-to-HEAD diff, index/worktree changes, and untracked source files, filtered by include/exclude. Deleted files are excluded. No changed source files produce an explicit empty result, never a whole-repo fallback.
- API errors use the documented error shape. The dashboard reads `GAUNTLET_RUNS_DIR` when explicitly configured (never silently substitutes samples for a broken live directory), otherwise local `.gauntlet/runs`, then bundled `sample-runs`. Responses identify sample versus live data.
- A GitHub workflow reports a check; merge blocking also requires branch protection configured by the repository owner.

## 3. Survivor handoff to Bob: `.gauntlet/survivors.md`

Generated by `gauntlet strengthen` before invoking Bob; consumed by the Skill. Markdown, not JSON, because it is prompt context.

```markdown
# Surviving mutants (run 1758945600-a1b2c3d)
Trust Score: 41.4% | Threshold: 80%

## src/pricing.ts
- [m-017] line 42 ConditionalExpression
  original: `if (qty >= bulkThreshold)`
  mutated:  `if (qty > bulkThreshold)`
  meaning: no test pins the boundary qty == bulkThreshold
```

## 4. Bob Skill: `.bob/skills/strengthen-tests/SKILL.md`

```markdown
---
name: strengthen-tests
description: Kill surviving mutants by writing sharper tests. Trigger when asked
  to strengthen tests or when .gauntlet/survivors.md is referenced.
---
Read .gauntlet/survivors.md. For each surviving mutant, write the smallest test
that fails on the mutated code and passes on the original. Rules:
- Do not modify source files; only test files.
- Do not delete or weaken existing assertions.
- Prefer boundary-value cases; name tests after the behavior, not the mutant id.
- Analyze survivors file by file; delegate per-file analysis to subagents when
  more than 3 files are affected.
- Run the full test suite before finishing; all tests must pass on original code.
```

## 5. Bob Hook: `.bob/settings.json` (fragment installed by `gauntlet init`)

```json
{
  "hooks": {
    "Stop": [
      { "hooks": [{ "type": "command", "command": "gauntlet run --changed --trigger hook", "timeout": 300 }] }
    ]
  }
}
```

The `Stop` event and nested `hooks` array follow [IBM's lifecycle hook documentation](https://bob.ibm.com/docs/ide/configuration/lifecycle-hooks), checked during implementation. The installer patches rather than overwrites the file. Actual invocation still requires a local IBM Bob installation. Bob Shell accepts a prompt on stdin via `bob run` ([official reference](https://bob.ibm.com/docs/shell/getting-started/start-bobshell-non-interactive)).

## 6. Dashboard API

Base: same-origin Next.js API routes. No auth (local/demo tool).

**GET /api/runs**
- Response: `[{ runId, createdAt, trigger, totals }]`, newest first, max 50.

**GET /api/runs/:runId**
- Response: the full run artifact.
- Errors: 404 `{ "error": "run not found" }`.

**GET /api/compare?a=:runId&b=:runId**
- Response: `{ a, b, delta: { trustScore, killed, survived }, perFile: [...] }`.

Error format everywhere: `{ "error": string }`.

## 7. CLI exit codes

| Code | Meaning |
|---|---|
| 0 | Success (gate: score >= threshold) |
| 1 | Gate failed: Trust Score below threshold |
| 2 | Run failed: Stryker or test command error |
| 3 | Config/environment error (no git repo, missing config) |

## 8. GitHub Action: `.github/workflows/gauntlet.yml`

```yaml
name: gauntlet-gate
on: [pull_request]
jobs:
  trust:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci
      - run: go run ./cmd/gauntlet run --changed --trigger ci
      - run: go run ./cmd/gauntlet gate --min-score 80
```
